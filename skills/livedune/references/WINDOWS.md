# LiveDune на Windows — проверка пользователем

Адаптер подготовлен, но настоящее Windows-устройство здесь не проверялось. Локальные подставные ответы не подтверждают Credential Manager, права файлов или браузер. До успешной проверки пользователя статус Windows — USER_CHECK_REQUIRED. Версию ОС, Node, Windows PowerShell и фактически загруженных пакетов сохранить в приватном результате. Другие скиллы не получают поддержку Windows автоматически.

## Ключ и рабочая папка

Используется штатный Windows PowerShell5.1 из SystemRoot/System32/WindowsPowerShell/v1.0 и .NET/WinCred, без новой библиотеки или HTTP-клиента. Фиксированные команды передаются через stdin; ключа во входных командах нет. Настройки защиты, execution policy и корпоративные ограничения не менять. AllSigned и принудительный Restricted в MachinePolicy/UserPolicy останавливают помощник; запрет запуска или Add-Type также останавливает API. При таком отказе предложить разрешённый сайт/ручную выгрузку или согласованный с IT способ запуска; защиту не отключать.

Пользователь сохраняет **общие учётные данные** в Диспетчере учётных данных Windows: адрес `ReportKit/LiveDune`, имя `LiveDune`, поле пароля — его API-ключ LiveDune. Делать это в системном окне, не через чат или команду с ключом. При необходимости агент помогает открыть нужное окно и показывает один шаг за раз; сам ключ не читает с экрана. Удаление/замена этой записи выполняются пользователем там же. Подключение к сайту и право на API проверяются отдельно.

`mcp-run.mjs --check-credential true` читает только указанную запись и сообщает `credential_available:true`, без значения. Этот шаг требует разрешённого доступа к ключу сотрудника. Никакого поиска других ключей, файлов, cookies или запасного токена из окружения. Переменные среды и обычные файлы не служат хранилищем ключа. Между дочерним процессом и адаптером значение передаётся через захваченный канал вывода, который нельзя сохранять в журнал; ошибки очищаются от подробностей. Это не обещание полного стирания управляемой памяти или изоляции от других программ того же пользователя/администратора.

До записи запросов агент запускает `mcp-run.mjs --prepare-private-dir <выбранная-папка-вне-пакетов>`. Он создаёт новую локальную папку с доступом текущего пользователя и наследованием этих прав файлами. Существующую папку только проверяет вместе с содержимым: не меняет её владельца/права и не следует ссылкам. При отказе предложить новую пустую рабочую папку, не ослаблять проверку. Сетевые папки для этого способа не принимаются. `calls.json` записывать внутри подготовленной папки; его права также проверяются до API. Прежние run-dir и requests.jsonl при продолжении сохраняются; новый каталог не обход лимита.

Для общей UI-очереди проверить существующий единственный store по [правилам очереди](../../_shared/UI-QUEUE.md). Её каталог тоже должен иметь проверенные приватные права; обычный chmod этого на Windows не подтверждает. Не создавать вторую очередь и не переносить чужую. Браузерный вход пользователя делать через штатный диалог с агентом с освобождением очереди; не использовать консольный wait_for_enter как доказанно работающий Windows-маршрут.

## Порядок проверки

1. После отдельно разрешённой установки агент запускает `node <skill>/scripts/check-windows.mjs --run-dir <новая-приватная-папка>`. Проверяются реальные ACL папки и тестового файла, повторный доступ к папке и остановка при отсутствующей записи ключа. После сохранения ключа и разрешения его чтения повторить с `--check-credential true`. Проверочный файл синтетический; его hash/результат сохраняются, файл удаляется. Приватный JSON-отчёт остаётся в run-dir; ключей, SID и имени пользователя в нём нет. Статус NATIVE_LOCAL_CHECKS_COMPLETED не является проверкой API, браузера или всего комплекта.
2. На разрешённом аккаунте и периоде согласовать небольшой лимит, например до3API-запросов: info, поиск выбранного сообщества и analytics. Использовать прежний готовый runtime/MCP, полный raw response и текущий ledger; `--cap` передавать явно. Права и доступные поля проверить по факту, не подменять недоступность нулём. После неизвестного результата не повторять запрос вслепую.
3. Открыть тот же источник/период в LiveDune, сначала во внутреннем браузере, если доступен. Проверить светлую тему, нужный показатель и штатное скачивание Excel; для снимков соблюдать общий порядок скилла. Сверить выбранный показатель с API по одинаковому определению. Возможное расхождение сохранить с источниками и временем; не подгонять цифры. При отсутствии управления браузером пользователь скачивает файл сам; такой результат маркировать MANUAL_EXPORT, а управление браузером — NOT_RUN/UNAVAILABLE.
4. Перезапустить приложение, повторить локальную проверку ключа и прав в той же рабочей области. Для проверки перезапуска не нужен новый API-запрос. Сохранить найденные ошибки и итог пользователя. API, сайт/ручная выгрузка и перезапуск имеют отдельные статусы; при частичном результате не объявлять всю Windows-поддержку проверенной.

В установленном mcp-openapi0.3.0 используется InMemoryTransport, сервер разработки esbuild не запускается. Предупреждение GHSA-g7r4-m6w7-qqqr для esbuild0.27.7 остаётся условным риском режима Windows development server, не объявлено исправленным. Такой режим не входит в этот адаптер. До его добавления отдельно обновить/проверить совместимую зависимость; без этого не расширять способ запуска.
