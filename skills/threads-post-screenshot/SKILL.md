# Скриншоты постов Threads

## Масштаб и ресурсы снимков

Перед съёмкой прочитай [общий порядок](../_shared/SCREENSHOTS.md).
По умолчанию штатные **75%**; проверь фактический масштаб и итоговую читаемость.
При нечитаемом тексте или неподдерживаемом native zoom — 100% и пересъёмка.
Склейку оставляй для реальных кадров прокрутки; проверяй новую геометрию и швы.
Закрывай обработанные изображения и удаляй свои ненужные промежуточные кадры.

Для штатных 75% запускай с `--headed`; без окна остаётся прежний headless
на 100%, с явным `zoom_fallback: native_headless_100`. Для пересъёмки — `--zoom 100`.

## Общая очередь интерфейса

Перед любым управлением браузером или приложением прочитай
[общий порядок](../_shared/UI-QUEUE.md) и получи активный билет через
`../_shared/ui_queue.py`. Одна FIFO-очередь действует
для всех личных скиллов и чатов, независимо от платформы и аккаунта.
Удерживай доступ до сохранения и проверки результата, очистки своих временных
вкладок и завершения действий в UI. Переиспользуй рабочую вкладку, выполняй
ссылки последовательно; пользовательские вкладки, чужие вкладки и авторизацию
сохраняй. Освобождай свой билет при завершении, ошибке, отмене и перед ручным
входом; после входа получай новый доступ и проверяй текущее состояние интерфейса.
Вложенным скиллам/скриптам передавай уже активный `PERSONAL_UI_QUEUE_TOKEN`;
они не создают второй билет и не освобождают родительский. Чтение файлов,
расчёты и API без управления UI очереди не требуют. Чужой активный билет
по таймеру не удаляй.

Для конкретных публичных постов Threads запускай `scripts/threads_post_screenshot.py`.
Передавай ссылки отдельными аргументами; `--output` задаёт папку PNG. Скриншот
содержит карточку исходного поста в светлой теме: автор, текст, медиа в том виде,
в котором их показывает страница, и реакции. Комментарии и окно входа исключаются.

```sh
PYTHON \
  scripts/threads_post_screenshot.py \
  'https://www.threads.com/share/ExamplePost/'
```

По умолчанию файлы сохраняются во внешнем REPORT_SKILLS_STATE_DIR/outputs/threads-screenshots.
Для прямой ссылки исходный и конечный ID должны совпадать; иначе снимок не сохраняется. Для /share/ сохранить проверенную постоянную ссылку в resolved_url.
Каждая строка stdout — JSON с `ok`, исходным `url`, подтверждённым `resolved_url` и либо абсолютным `path`,
либо `error`. При нескольких ссылках верни успешные изображения и назови ошибки.
Перед ответом просмотри PNG: содержимое должно быть читаемым, без комментариев
и затемнения. Если Threads требует входа или пост недоступен, сообщи об этом;
не проси пароль в чате и не обходи ограничения доступа.



## Переносимая работа

PYTHON в примерах — выбранный и проверенный внешний runtime сотрудника. Установка зависимостей разрешается отдельно по фактическому requirements/catalog; окружение и сессии не создаются внутри пакета. Для CUA/Pillow/NumPy проверить соответствующие возможности среды до запуска. Скрипты и общий помощник очереди разрешать относительно этой папки; outputs и state сохранять только во внешней private workspace. Работу на устройстве сотрудника, доступ и итоговые PNG проверять фактически: наличие файлов и прошлый пример не подтверждают готовность.

[Порядок сопровождения](../_shared/MAINTENANCE.md) сохраняет pause, budget и разрешённые маршруты; callback не заменяет успешную проверку в исходной задаче.
