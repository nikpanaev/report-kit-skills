# Скриншоты постов MAX

## Масштаб и ресурсы снимков

Перед съёмкой прочитай [общий порядок](../_shared/SCREENSHOTS.md).
По умолчанию штатные **75%**; проверь фактический масштаб и итоговую читаемость.
При нечитаемом тексте или неподдерживаемом native zoom — 100% и пересъёмка.
Склейку оставляй для реальных кадров прокрутки; проверяй новую геометрию и швы.
Закрывай обработанные изображения и удаляй свои ненужные промежуточные кадры.

## Общая очередь интерфейса

Перед любым управлением браузером или приложением прочитай
[общий порядок](../_shared/UI-QUEUE.md) и получи активный билет через
`../_shared/ui_queue.py`. Одна FIFO-очередь действует
для всех личных скиллов и чатов, независимо от платформы и аккаунта.
Удерживай доступ до сохранения и проверки результата, очистки своих временных
вкладок и завершения действий в UI. Переиспользуй рабочую вкладку, выполняй
ссылки последовательно; пользовательские вкладки, чужие вкладки и авторизацию
сохраняй. Освобождай свой билет при завершении, ошибке, отмене и перед ручным
входом; после входа получай новый доступ и проверяй текущее состояние интерфейса.
Вложенным скиллам/скриптам передавай уже активный `PERSONAL_UI_QUEUE_TOKEN`;
они не создают второй билет и не освобождают родительский. Чтение файлов,
расчёты и API без управления UI очереди не требуют. Чужой активный билет
по таймеру не удаляй.

Снимай реальный пост в приложении или авторизованной веб-версии MAX через доступный
инструмент управления интерфейсом (`cua_repl`). Это отдельный скилл: для Telegram используй
`$telegram-post-screenshot`, для VK — `$vk-post-screenshot`.
Ссылка на канал без ID не задаёт публикацию — запроси ссылку на конкретный пост.

## Превью не является полным постом

`https://max.ru/канал/ID` может открывать маленькую карточку перехода в приложение.
Превью может содержать обрезанный текст и миниатюры.
Наличие полного текста в accessibility-дереве не подтверждает полноценную страницу.
Не выдавай эту карточку за пост, не увеличивай миниатюру и не рисуй свою верстку
по её тексту. Для полного снимка используй авторизованный клиент.

## Съёмка

Снимай только в светлой теме. Перед съёмкой включи светлую тему штатным
переключателем приложения или веб-клиента и проверь её на экране. Все кадры одного
поста должны иметь одинаковую тему. Не осветляй готовый PNG, не инвертируй цвета
и не подменяй оформление клиента через CSS. Если светлую тему включить не удалось,
сообщи ограничение; тёмный снимок не выдавай как готовый результат.

Кадрируй тело по границам самой карточки публикации с минимальным отступом:
широкое поле обоев справа не включай. Шапку обрезай отдельно так, чтобы полностью
сохранить аватар и полное название канала. Поиск, меню и стрелку назад убирай
по возможности, сохраняя целый заголовок и исходные пиксели.
Если шапка шире карточки, соединяй отдельные обрезки исходных пикселей без
уменьшения текста и дорисовки фона. Дату сохраняй целиком. Координаты определяй
по текущему снимку; перед выдачей проверь, что название и содержимое не обрезаны.

1. Используй приложение или браузер/вкладку, указанные пользователем. Иначе предпочитай
   авторизованный MAX Web (`https://web.max.ru`): этот путь проверен целиком.
   Альтернатива — уже авторизованное приложение MAX; на macOS идентификатор приложения — `ru.oneme.desktop`. Не считай установку доказательством входа.
   Соблюдай документацию доступного инструмента и считывай свежую
   страницу после действий.
2. Если показан вход, открой вкладку пользователю и предложи войти самостоятельно
   по QR-коду или номеру. Не проси прислать пароль/код и не считай отсутствие ответа
   выполненным входом. Продолжи после подтверждения или видимой авторизации.
   При «слишком много попыток» прекрати вход; не повторяй его до согласованного
   пользователем времени. Уже авторизованное приложение можно использовать.
3. Открой нужный канал/пост через элементы текущего интерфейса. Публичная страница
   может открыть установленное приложение по deeplink: после перехода проверь
   состояние приложения. Для Web используй наблюдаемую ссылку «Открыть в браузере» на публичной
   странице поста. Не придумывай схему маршрутизации веб-клиента: проверь,
   что переход действительно открыл нужную публикацию. При необходимости
   найди канал по имени и публикацию по её тексту/дате, затем сверяй ссылку через
   доступное действие «Скопировать ссылку». Сам текст превью служит ориентиром,
   но не заменяет проверку ID. Не подписывайся и не отправляй сообщения ради съёмки.
4. Дождись реальных фото/альбома и раскрой текст доступным действием интерфейса.
   Снимай только выбранную публикацию с видимым названием/аватаркой канала,
   текстом, вложениями и доступной датой/реакциями. Исключи соседние публикации,
   боковую панель, обсуждение и форму ответа. Геометрию области снимка определяй
   по текущему DOM или свежему снимку окна; не переноси селекторы VK и не угадывай
   MAX-классы. В длинном посте AX-элемент текста может иметь центр за пределами окна:
   если клик сообщает, что элемент вне экрана, используй видимую часть на снимке.
5. Один пост должен дать один итоговый PNG в `outputs/max-screenshots` рабочей
   папки текущего чата либо в папке пользователя. Для длинного поста снимай
   промежуточные кадры с перекрытием минимум 200 px и собери один длинный PNG:
   заголовок канала один раз, текст и альбом без повторов и пропусков.
   Части не выдавай как готовый результат. Не уменьшай готовый PNG ради одного кадра;
   штатные 75% допустимы только при проверенной читаемости по общему порядку.
6. Просмотри PNG перед выдачей: заголовок, содержимое и медиа читаемы, нет превью,
   комментариев или соседних постов. Верни снимки через
   Markdown-изображение с абсолютным путём готового PNG; при неудаче сообщи конкретную причину.

Видео показывается как доступный кадр/обложка. Если вложение недоступно или ID
поста не подтверждён, не объявляй снимок полным и не подменяй пост.

Кнопку перехода к комментариям самого поста можно оставить; содержание
обсуждения не включай.

## Собрать длинный PNG из кадров

Используй [scripts/stitch_post_screenshots.py](scripts/stitch_post_screenshots.py)
для одинаково обрезанных кадров: только область поста и неподвижный заголовок,
без бокового списка и формы ввода. Параметры области определяй по конкретным
кадрам, не переноси координаты другого окна. Сопоставление выполняется внутри
самой карточки поста, чтобы неподвижный фон/полоса прокрутки не дали ложный шов.

```sh
PYTHON \
  scripts/stitch_post_screenshots.py \
  КАДР_1.png КАДР_2.png КАДР_3.png \
  --header ВЫСОТА_ЗАГОЛОВКА --match-left ЛЕВЫЙ_X --match-right ПРАВЫЙ_X \
  --output ИТОГОВЫЙ.png
```

Пример запускай из папки этого скилла; пути кадров и результата укажи абсолютными
в рабочей папке задачи. Координаты в пикселях PNG. Скрипт сопоставляет перекрытие, сохраняет заголовок
первого кадра и отказывается соединять неуверенные совпадения. При отказе
пересними перекрытие; не склеивай кадры простым вертикальным сложением.
Сглаживаются только отпечатки для сопоставления JPEG/субпиксельных различий;
пиксели итогового снимка берутся из исходных кадров без сглаживания.
Просмотри итог полностью и каждый шов: непрерывность строк, целый альбом,
реакции/дата, отсутствие дублированных абзацев и соседних постов.
Если полный PNG не удалось получить, сообщи ошибку вместо выдачи набора частей.
Проверка сборки: тем же Python запусти `scripts/test_stitch_post_screenshots.py`.



## Переносимая работа

PYTHON в примерах — выбранный и проверенный внешний runtime сотрудника. Установка зависимостей разрешается отдельно по фактическому requirements/catalog; окружение и сессии не создаются внутри пакета. Для CUA/Pillow/NumPy проверить соответствующие возможности среды до запуска. Скрипты и общий помощник очереди разрешать относительно этой папки; outputs и state сохранять только во внешней private workspace. Работу на устройстве сотрудника, доступ и итоговые PNG проверять фактически: наличие файлов и прошлый пример не подтверждают готовность.

[Порядок сопровождения](../_shared/MAINTENANCE.md) сохраняет pause, budget и разрешённые маршруты; callback не заменяет успешную проверку в исходной задаче.
