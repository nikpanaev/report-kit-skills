# Комментарии к постам MAX

## Масштаб и ресурсы снимков

Перед съёмкой прочитай [общий порядок](../_shared/SCREENSHOTS.md).
По умолчанию штатные **75%**; проверь фактический масштаб и итоговую читаемость.
При нечитаемом тексте или неподдерживаемом native zoom — 100% и пересъёмка.
Склейку оставляй для реальных кадров прокрутки; проверяй новую геометрию и швы.
Закрывай обработанные изображения и удаляй свои ненужные промежуточные кадры.

## Общая очередь интерфейса

Перед любым управлением браузером или приложением прочитай
[общий порядок](../_shared/UI-QUEUE.md) и получи активный билет через
`../_shared/ui_queue.py`. Одна FIFO-очередь действует
для всех личных скиллов и чатов, независимо от платформы и аккаунта.
Удерживай доступ до сохранения и проверки результата, очистки своих временных
вкладок и завершения действий в UI. Переиспользуй рабочую вкладку, выполняй
ссылки последовательно; пользовательские вкладки, чужие вкладки и авторизацию
сохраняй. Освобождай свой билет при завершении, ошибке, отмене и перед ручным
входом; после входа получай новый доступ и проверяй текущее состояние интерфейса.
Вложенным скиллам/скриптам передавай уже активный `PERSONAL_UI_QUEUE_TOKEN`;
они не создают второй билет и не освобождают родительский. Чтение файлов,
расчёты и API без управления UI очереди не требуют. Чужой активный билет
по таймеру не удаляй.

Снимай реальное обсуждение через `cua_repl` в приложении или авторизованном MAX Web.
Для публикации используй `$max-post-screenshot`, для комментариев Telegram —
`$telegram-comment-screenshot`, VK — `$vk-comment-screenshot`.

## Открыть нужное обсуждение

Используй указанный пользователем клиент; иначе предпочитай уже авторизованный
MAX Web. Нужна ссылка `max.ru/канал/ID`: для ссылки без ID запроси конкретный пост.
Публичная страница может быть маленьким превью, даже если DOM содержит весь текст.
Используй наблюдаемое «Открыть в браузере», не придумывай маршрут веб-клиента.
При отсутствии сессии предложи самостоятельный вход; пароль/код не запрашивай.
При «слишком много попыток» прекрати вход до согласованного пользователем времени.

Проверь исходный пост и его ID через доступное действие «Скопировать ссылку на
пост». Числовой URL канала после перехода не подтверждает выбранную публикацию.
В проверенном внутреннем браузере скопированная ссылка попадала в системный,
а не виртуальный буфер. При необходимости проверь её вставкой в новый временный
документ через UI; не используй пользовательский документ или чат и не считай
пустой виртуальный буфер доказательством отсутствия ссылки. Не подписывайся ради
съёмки и не отправляй сообщений.

Сними настоящую шапку канала с аватаром и полным названием, затем открой кнопку
комментариев внутри выбранной публикации. Подтверди экран «Комментарии» и связь
с исходным постом; весь пост может находиться перед началом ветки — исключи его
из итоговой области. Если комментарии отключены или недоступны, сообщи это;
не выдавай превью или кнопку перехода за обсуждение.

## Кадрирование и сохранение

По умолчанию снимай в светлой теме, включённой штатным переключателем клиента.
Другую тему используй только по явному запросу пользователя. Перед съёмкой проверь
фактическую тему интерфейса, а перед выдачей — итоговый PNG. Если светлая тема
недоступна, явно сообщи ограничение. Цвета исходных фото и видео не меняй.
Не осветляй PNG, не меняй оформление через CSS и не создавай карточки по тексту.
Сохрани контекст исходного поста: видимое название канала и аватар либо нативное
превью/миниатюру поста. Если экран обсуждения не показывает канал, отдельно сними
его настоящую шапку до открытия комментариев и добавь полосу исходных пикселей.

Снимай все доступные комментарии и ответы выбранного обсуждения. Раскрой
видимые кнопки ответов и загрузки предыдущих/следующих сообщений. При прокрутке
проверяй появление новых сообщений; остановись, когда достигнуты доступные начало
и конец ветки и новых сообщений больше нет. Счётчик может включать ответы автора:
не требуй столько же корневых комментариев. Цитата в ответе не является ещё одним
сообщением. Сохраняй автора, аватар, полный текст, вложения, цитату/связь ответа,
время и реакции, если клиент их показывает. Недоступные ответы не восстанавливай.

Обрезай область по фактическим границам обсуждения с небольшим отступом.
Исключи список чатов, поле ввода, соседние обсуждения и полный текст исходного
поста; короткое нативное превью оставь для контекста. Сохраняй расположение
ответов справа/слева, если так их показывает клиент. Не обрезай имена или текст
ради удаления фона. Плавающая дата не должна перекрывать текст или маркер начала
обсуждения: прокрути область, дождись завершения движения и проверь снимок.
Координаты снимка и DOM могут различаться; измеряй текущий PNG, не копируй числа
из примера. Можно соединить отдельные полосы одного реального кадра, исключив
промежуток с полным постом, без дорисовки фона и уменьшения готового PNG.

Одно обсуждение — один итоговый PNG. Для длинной ветки снимай кадры с перекрытием
минимум 200 px и используй уже установленный общий помощник
`../max-post-screenshot/scripts/stitch_post_screenshots.py` относительно папки
этого скилла. Он работает с пикселями любой площадки и не открывает MAX.
Используй проверенный слой images (Pillow и NumPy) подготовленной среды Report Kit. Историческая проверка другого компьютера не подтверждает готовность сотрудника.

```sh
PYTHON ../max-post-screenshot/scripts/stitch_post_screenshots.py \
  КАДР_1.png КАДР_2.png --header ВЫСОТА_ШАПКИ \
  --match-left ЛЕВЫЙ_X --match-right ПРАВЫЙ_X --output ИТОГ.png
```

В примере замени параметры геометрией текущих кадров в пикселях PNG; сопоставляй
внутри движущихся карточек, исключая неподвижный фон. При отказе проверки пересними
с большим перекрытием; не снижай порог и не складывай кадры с повторами. Если
помощник недоступен, не выдавай набор частей за полный результат.
Просмотри весь итог, включая швы и крайние сообщения. Сверь доступный состав
ветки с кадром: нет пропусков, повторов или обрезанных вложений. Если полноту
подтвердить нельзя, сообщи конкретное ограничение вместо заявления «всё снято».

Сохрани результат в `outputs/max-comment-screenshots` рабочей папки задачи
либо в папке пользователя и покажи через Markdown-изображение с абсолютным путём готового PNG.



## Переносимая работа

Прочитай [правила подготовленной среды](../_shared/RUNTIME.md). PYTHON в технических примерах обозначает запуск, подготовленный агентом через runtime.execution_plan выбранного report-kit-agent, с проверенными interpreter, библиотеками и окружением; это не команда для сотрудника и не поиск Python в PATH. Для обработки кадров нужны слои Pillow, для браузерных сценариев — Playwright и отдельно проверенный браузер. Подготовку необходимых компонентов агент выполняет после согласия, без ручной установки библиотек сотрудником. Пути скриптов разрешай относительно этого скилла, результаты и сессии — только во внешней выбранной рабочей папке. Наличие файлов не подтверждает работу на устройстве или доступ к сервису.

[Порядок сопровождения](../_shared/MAINTENANCE.md) сохраняет pause, budget и разрешённые маршруты; callback не заменяет успешную проверку в исходной задаче.
