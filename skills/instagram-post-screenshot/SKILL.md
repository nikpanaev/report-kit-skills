# Скриншоты постов Instagram

## Масштаб и ресурсы снимков

Перед съёмкой прочитай [общий порядок](../_shared/SCREENSHOTS.md).
По умолчанию штатные **75%**; проверь фактический масштаб и итоговую читаемость.
При нечитаемом тексте или неподдерживаемом native zoom — 100% и пересъёмка.
Склейку оставляй для реальных кадров прокрутки; проверяй новую геометрию и швы.
Закрывай обработанные изображения и удаляй свои ненужные промежуточные кадры.

Мобильная эмуляция сохраняет проверенные 100%: Chromium игнорирует в ней
штатный zoom. В JSON проверяй `browser_zoom` и `zoom_fallback: native_mobile_100`.

## Общая очередь интерфейса

Перед любым управлением браузером или приложением прочитай
[общий порядок](../_shared/UI-QUEUE.md) и получи активный билет через
`../_shared/ui_queue.py`. Одна FIFO-очередь действует
для всех личных скиллов и чатов, независимо от платформы и аккаунта.
Удерживай доступ до сохранения и проверки результата, очистки своих временных
вкладок и завершения действий в UI. Переиспользуй рабочую вкладку, выполняй
ссылки последовательно; пользовательские вкладки, чужие вкладки и авторизацию
сохраняй. Освобождай свой билет при завершении, ошибке, отмене и перед ручным
входом; после входа получай новый доступ и проверяй текущее состояние интерфейса.
Вложенным скиллам/скриптам передавай уже активный `PERSONAL_UI_QUEUE_TOKEN`;
они не создают второй билет и не освобождают родительский. Чтение файлов,
расчёты и API без управления UI очереди не требуют. Чужой активный билет
по таймеру не удаляй.

Работай в локальном чате Codex с разрешёнными инструментами управления интерфейсом. Принимай ссылки на конкретные
публикации `/p/SHORTCODE/` и `/reel/SHORTCODE/`; профиль и лента не задают пост.
Сторис и комментарии требуют другого способа.

## Выбрать режим по запросу

| Запрос | Аргументы | Результат |
|---|---|---|
| Без уточнений | без флагов | Первое фото и короткая подпись; у Reel — настоящий кадр на 4-й секунде |
| Все картинки карусели | `--all-images` | Каждый слайд отдельным PNG с короткой подписью |
| Весь пост / полный текст | `--full-text` | Первое фото или кадр видео вместе со всей подписью |
| Все картинки и весь текст | `--all-images --full-text` | Каждый слайд со всей подписью |

Для явно указанного момента видео добавь `--video-seconds N`. По умолчанию это
4 секунды (согласованный диапазон 3–5); у более короткого видео берётся последний
доступный кадр, фактическое время возвращается в `frame_times`.

Снимки имеют мобильную ширину 390 CSS px и двойное разрешение: PNG шириной 780 px.
Пост снимается с мобильной страницы Instagram, текст остаётся естественно свернутым.
Полный текст снимается через встроенный вид Instagram: заголовок отличается и
даты нет. Это особенность существующего режима, а не приёмка оформления новым сотрудником; до использования согласуй его пригодность для отчёта. Для видео в эту карточку загружается
видео того же поста и выставляется нужный момент; обложку не выдавай за кадр видео.
Видеослайды карусели также снимаются на указанной секунде.
Если встроенный вид предоставляет только обложку видеослайда, сообщи ошибку
полного режима; не подменяй настоящий кадр обложкой.

## Получить PNG

Агент разрешает путь scripts/instagram_post_screenshot.py относительно папки этого скилла и запускает его подготовленной средой. Ссылки передавай отдельными аргументами
процесса; при использовании shell экранируй каждый аргумент.

```sh
PYTHON \
  scripts/instagram_post_screenshot.py \
  'https://www.instagram.com/p/ExamplePost/'
```

Можно передать несколько ссылок. Папка по умолчанию — `REPORT_SKILLS_STATE_DIR/outputs/instagram-screenshots`; выбранная внешняя папка запуска задаётся через `--output`. Режимы имеют разные имена
файлов, повторная съёмка того же поста в том же режиме заменяет его PNG.

Stdout — JSON Lines, один результат на ссылку. Успех: `ok: true`, `paths` — список
абсолютных путей, `frame_times` — моменты видео или `null` для фото.
Ошибка: `ok: false`, `error`. Код `1` допускает частичный успех пакета:
верни готовые снимки других ссылок и сообщи, что не удалось снять.
Не повторяй неудачный запуск бесконечно: максимум одна дополнительная попытка
с `--headed` или после ручного входа.

Просмотри каждый PNG перед выдачей: автор, аватар, медиа и нужная часть подписи
должны быть видны. Баннеры входа, комментарии и форма комментария в снимки не
входят; значки и счётчики реакций сохраняются. Если видны комментарии или перекрытия,
исправь снимок, прежде чем выдавать его как готовый. Возвращай изображения через
Markdown с абсолютными путями из `paths`.

## Если нужен вход

Сначала попробуй без входа. При требовании авторизации предложи ручной вход:
запусти ту же программу с `--login` в интерактивном терминале, пользователь входит
в открытом браузере и сообщает в чат, что вход завершён. Подтверждение Enter в собственном интерактивном процессе передаёт агент; при отсутствии такого инструмента этот способ не объявлять доступным. Сессия сохраняется в
внешнем приватном `instagram-session.json` выбранного хранилища и доступна локальным чатам.
Не проси пароль в чате. Закрытый пост без доступа, отключённое встраивание и
удалённые публикации не выдавай за успешно снятые.



## Переносимая работа

Прочитай [правила подготовленной среды](../_shared/RUNTIME.md). PYTHON в технических примерах обозначает запуск, подготовленный агентом через runtime.execution_plan выбранного report-kit-agent, с проверенными interpreter, библиотеками и окружением; это не команда для сотрудника и не поиск Python в PATH. Для обработки кадров нужны слои Pillow/NumPy, для браузерных сценариев — Playwright и отдельно проверенный браузер. Подготовку необходимых компонентов агент выполняет после согласия, без ручной установки библиотек сотрудником. Пути скриптов разрешай относительно этого скилла, результаты и сессии — только во внешней выбранной рабочей папке. Наличие файлов не подтверждает работу на устройстве или доступ к сервису.

[Порядок сопровождения](../_shared/MAINTENANCE.md) сохраняет pause, budget и разрешённые маршруты; callback не заменяет успешную проверку в исходной задаче.
