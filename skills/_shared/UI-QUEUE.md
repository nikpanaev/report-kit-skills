# Одна очередь UI

Все UI skills этого пакета используют ui_queue.py из этой папки и один external store REPORT_SKILLS_STATE_DIR/queue.sqlite3. Store общий для чатов, аккаунтов и типов контента на устройстве. Перед UI получить access/queued; при вложенном вызове сохранить PERSONAL_UI_QUEUE_TOKEN, не создать второй билет и не освобождать родительский.

FIFO удерживается до сохранения/проверки результата, очистки собственных вкладок и конца UI. Сохранять пользовательские вкладки/авторизацию; чужой активный ticket не удалять по таймеру. При отмене/error/finally освободить свой билет. Перед ручным входом handoff освобождает собственный ticket; после новый ticket и повторная проверка экрана. Borrowed ticket не делает самостоятельный login: родитель обязан передать управление.

API/файлы/расчёты без управления интерфейсом очереди не требуют. При coexistence с другими installed skills сначала проверить и согласовать единственный store; default этого нового пакета не разрешает вторую конкурирующую очередь. Existing legacy stores на текущем устройстве не меняются.

Текущая реализация uses POSIX select/signals. На другой ОС проверка обязательна, Windows пока NOT_VERIFIED. Не заменять очередь обходом отказа доступа.

## После аварийного закрытия

Скриптовые Lease сохраняют локальный PID/host каждого владельца и заимствующего дочернего процесса во вспомогательной таблице того же store. Билет снимается только когда все зарегистрированные процессы подтверждённо завершились; живой дочерний процесс удерживает очередь после смерти родителя. Возраст билета не критерий. На Windows используются OpenProcess/WaitForSingleObject без завершения процесса; неизвестное состояние, отказ, другой host или переиспользованный живой PID сохраняют блокировку. Нативная Windows-проверка остаётся USER_CHECK_REQUIRED.

Legacy/manual билеты без проверяемого владельца не истекают. Агент проверяет исходную задачу штатными средствами и объясняет владельцу точное зависшее задание; освобождение такого билета — только после подтверждения, что его UI-действия закончены, по исходному token. Не удалять базу целиком и не создавать второй store. Новый контракт shared:ui_queue=2 требует проверки старых клиентских требований при обновлении; профили автоматически не менять.
