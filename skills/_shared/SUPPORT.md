# Безопасные сведения для поддержки

Прежние request/retry/maintenance logs не отправляются как есть. Они могут содержать ссылки, provider error body, личные пути и клиентские ID. Request ledger, budget, queue и recovery inputs сохраняют своё назначение и не очищаются по policy диагностики.

Минимальная safe-проекция событий описана в `support-policy.json`; Python реализация — `support_events.py`, Node writer — `support-events.mjs`. По просьбе пользователя применяется collector выбранного report-kit-agent (его точная копия того же кода). Standalone вариант: Python `support_events.py --state-dir <chosen external state>`. Ничего не отправляется. Эта техническая команда предназначена агенту, не сотруднику.

Разрешены только известные component/stage/kind/result/error/http, время, случайные UUID4/sequence и строго ограниченные версии известных программ. Нельзя передавать exception message/stacktrace, command output, raw response, URL/ID/параметры, имена/контент/переписку, телефон/почту, hostname/user/PID/пути, keys/password/cookies/session. Новая запись не копирует старую, а получает фиксированные поля в момент уже выполняющегося действия. Unknown значения становятся безопасными кодами; при export allowlist применяется снова. Наличие поля вне allowlist не делает его безопасным.

UI queue отражает acquire/release, browser helper — наблюдавшуюся версию Chromium, VK — существующий stage retry/result, LiveDune — STARTED/received/uncertain projection без request URL и provider body. Это не дополнительные HTTP-запросы и не новый retry policy. Диагностика best effort: отказ её записи не заменяет исходную ошибку/результат. Общий report run может использовать случайный REPORT_KIT_SUPPORT_RUN_ID; никаких хешей клиентских IDs.

Хранилище — выбранный `REPORT_SKILLS_STATE_DIR/support-v1`, рядом с прежним store, но отдельно от queue и API ledgers. До14 дней/2 000 событий/4МБ; ZIP до7 дней/3 по1МБ. Очистка только собственных распознанных диагностических файлов при следующей работе, без расписания. После crash сохраняются уже записанные события; незавершённая операция имеет неизвестный результат, автоматический replay запрещён прежними budget/recovery правилами.

Если записей нет, они повреждены или исключены, архив прямо говорит о неполноте. Никакого автоматического чтения общих папок, исходных журналов или восстановления данных из других клиентов. Запасной способ двойным нажатием готовит агент в выбранной private папке; для него используется заранее подготовленный проверенный Python Report Kit, работающий агент и аккаунты не нужны. При настройке передать prepare_fallback(..., python=<verified selected interpreter>); системный Python сотруднику не устанавливать. До успешной подготовки среды запасной способ может быть недоступен. Пользователь пересылает только итоговый ZIP. Windows проверяет пользователь на устройстве, не модель этого writer.
